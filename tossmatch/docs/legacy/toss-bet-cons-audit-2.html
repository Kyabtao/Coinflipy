⚠️ New cons — need your decision

#ConWhy it mattersOptions
AMutual referral exploitBoth players can refer each other (p1 → p2's code, p2 → p1's code). Both then earn 5% of each other's fees — a closed loop where the house pays referral cuts to both sides of the same game. In a two-player demo this is trivially exploitable; in production with collusion it bleeds fees.Block mutual links (if A referred B, B can't refer A) · or cap referral earnings at one link per account pair · or accept in the demo and document for production
BSingle-slot localStorageTwo browser tabs = two saves writing to the same key = the last writer wins. Refresh one tab and the other's state is gone. Not a bug (demo constraint) but confusing if someone opens the demo twice.Accept (demo) · or add a tab-ID suffix and warn on collision · or use a single BroadcastChannel owner
C×2 challenges never expireSpec says "optional expiry" but no expiry timer was implemented — a challenge sits in the waiting room forever until manually cancelled.Add a default TTL (e.g., 10 minutes) with auto-cancel + refund · or a visible timer on each challenge · or accept as-is for demo
DBank and vault are semantically identicalBoth park MAIN-balance coins outside the betting wallet. Two features doing the same thing is confusing UX — "why do I have a vault AND a bank?"Merge into one "Bank" feature (vault = quick-preset, bank = custom amount) · or rename vault to "quick park" and bank to "bank transfer" · or remove one
