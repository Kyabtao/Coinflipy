#ConWhy it mattersOptions
AMicro-stake margin leak (see #3 above)Stakes ≤ ~12 coins give the house 0% — a grid of 10-coin bots (or just grinders) runs fee-free while still feeding the jackpot and earning XP.Raise min stake to 25 · or fee minimum "max(1 coin, %)" instead of jackpot floor · or make the floor apply only when fee ≥ 2 · or accept it as a micro-stakes promo.
BNo persistenceRefresh = total wipe (balances, history, VIP month, everything). Feels like a toy for exactly the reason you called out.Add localStorage auto-save + "Continue / New session" on load. ~30 lines, low risk. Recommended next.
CWithdraw/deposit not in UISpec says deposits & withdrawals touch MAIN only; demo only has admin top-up. Transfers exist, withdrawals don't.Add a Withdraw card (MAIN → "bank", admin-processed in demo) + Deposit (bank → MAIN) with ledger entries.

🏭 Production-only (fine for play money, critical for real money)

#ConReality
1Everything is client-sideThe "server seed", escrow, rate limits, loss limits and balances all live in the visitor's browser. Fine as a spec showcase; meaningless as security. Production = server-authoritative engine, clients only render and sign.
2No accounts/auth; both players in one tabNo login, sessions, or identity. The two-player-one-screen model is the demo's core simplification.
3Admin tab unprotectedAnyone can open ⚙️ and change fees/reset. Production needs role-based auth + 2FA on money actions (already in the spec's checklist).
4Clock still device-controlledUTC unification helps consistency, but the browser clock is still settable — daily claims must be server-time in production.
5Fairness is self-attestedThe commit–reveal math is sound and test-vector verified, but with no independent server there's no external trust anchor. Production: seed committed server-side (HSM), client seeds hashed client-side, verifier as a public page, RNG lab certification.
6No KYC/AML, age or geo gatingNone implemented — licence conditions, not optional features, for real money.
7Anti-abuse is thinOne-per-account promos and a 12/min rate limit are demo-grade. Production needs device fingerprinting, velocity checks, collusion detection (two accounts dumping to one via transfers).
8Transfers have no fraud controlsNo confirmation step, no hold period, no chargeback story — real P2P transfers are the classic money-laundering vector and need limits + review queues.
9Single-file architecture~200KB one HTML file with no modules/tests shipped — great for portability, painful to maintain. Production = proper codebase + CI + the test suite moved into it.
